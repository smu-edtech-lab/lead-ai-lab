# 검토 요청 안내 — GitHub 계정 없이 홈페이지 고치기

교수님처럼 GitHub 계정이 없는 분이 홈페이지 내용을 고치는 방법입니다.
고친 내용은 바로 게시되지 않고 홈페이지 담당자에게 **검토 요청**으로 가며, 담당자가 확인한 뒤 사이트에 반영합니다.

| 무엇 | 주소 |
|---|---|
| 관리 화면 | <https://smu-edtech-lab.github.io/lead-ai-lab/admin> |
| 공개 사이트 | <https://smu-edtech-lab.github.io/lead-ai-lab/> |

- 비밀번호는 홈페이지 담당자에게 **직접** 받습니다. 이 문서나 단체 대화방에는 적지 않습니다.
- 1~5장은 요청하는 분(교수님 등), 6~9장은 요청을 받아 반영하는 홈페이지 담당자를 위한 내용입니다.
- 이 기능을 켜는 방법(담당자): [CMS-설정-안내.md 14장](CMS-설정-안내.md#14-검토-요청-켜기)

## 1. 들어가기

1. 관리 화면을 엽니다.
2. 아래쪽 **GitHub 계정이 없다면** 칸에 검토 요청 비밀번호를 넣고 **비밀번호로 들어가기**를 누릅니다.
3. 위쪽에 **검토 요청 모드** 안내가 보이면 들어온 것입니다.

- 들어온 상태는 **8시간** 유지되고, 브라우저 탭을 닫으면 끝납니다. 다시 비밀번호를 넣으면 됩니다.
- 공용 PC 에서는 다 쓴 뒤 오른쪽 위 **로그아웃**을 누르고 탭을 닫으세요.

## 2. 고칠 수 있는 것

| 화면에서 바로 고침 | 메모로 요청 |
|---|---|
| 소식, 구성원·졸업생(사진·소개·연구실적·수상·이력 포함), 논문·저역서·학술발표, 연구 과제 — 추가·수정·삭제, 구성원 순서, 졸업생으로 옮기기. **연구실 정보**(연구실 이름·슬로건·소개 문단, 소속·연락처, 교수 프로필·경력, 연구 분야 설명)와 **페이지 문구**(각 페이지 제목·소개 문장·섹션 제목·버튼 이름, Contact 의 자주 묻는 질문) — 고치는 동안 실제 페이지가 미리보기로 보입니다 | 화면 배치·디자인·색, 로고, 메뉴 구성, 연구 분야를 새로 만들거나 없애기, 그 밖에 화면에 칸이 없는 것 |

## 3. 고치고 요청 보내기

1. 왼쪽 메뉴(휴대폰은 위쪽 단추)에서 고칠 곳을 고릅니다.
2. 고칠 항목의 **고치기 →** 를 누릅니다. 새로 쓰려면 **+ 추가**를 누릅니다.
3. 칸을 고치면 옆의 미리보기가 바로 바뀝니다. **필수** 표시가 있는 칸은 꼭 채웁니다.
4. 맨 아래 **확인하고 요청 보내기**를 누르면, 바뀌는 칸이 지금 사이트의 내용과 나란히 보입니다.
5. 담당자에게 전할 말이 있으면 **담당자에게 남길 말**에 적고 **요청 보내기**를 누릅니다.

- 항목을 지우려면 편집 화면 맨 아래 왼쪽 **이 … 삭제** → **삭제 요청 보내기**를 누릅니다.
- 요청을 보낸 뒤에도 담당자가 반영하기 전까지는 목록에 **지금 사이트의 내용**이 보입니다. 고친 내용이 사라진 것이 아닙니다.
- 같은 항목을 반영 전에 또 고치면 요청이 하나 더 갑니다. 앞 요청과 겹칠 수 있으니, 가능하면 반영된 뒤에 고치거나 메모로 함께 알려 주세요.

## 4. 메모로 요청하기

화면에서 고칠 수 없는 것은 처음 화면의 **메모로 요청하기**에 적고 **메모 보내기**를 누릅니다.

예시
- Research 페이지 맨 위 소개 문장을 “…”로 바꿔 주세요.
- Home 첫 화면 사진을 연구실 단체 사진으로 바꿔 주세요. 사진은 메일로 보내겠습니다.
- People 페이지에서 졸업생 목록을 위로 올려 주세요.

## 5. 보낸 요청 확인하기

처음 화면의 **보낸 요청**에서 진행 상태를 볼 수 있습니다.

| 표시 | 뜻 |
|---|---|
| 검토 기다림 | 담당자가 아직 확인하기 전 |
| 사이트에 반영됨 | 반영했습니다. 1~2분 뒤 공개 사이트에서 보입니다 |
| 반영 안 함 | 담당자가 반영하지 않기로 했습니다. 요청을 누르면 담당자의 댓글(이유)을 볼 수 있습니다 |
| 처리 끝 | 메모 요청을 담당자가 처리했습니다 |

> **요청과 메모는 공개 저장소에 바로 올라가, 반영되기 전이라도 누구나 볼 수 있습니다.** 연락처·학번 같은 개인 정보는 적지 말고, 사진은 본인이 게시에 동의한 것만 올려 주세요.

## 6. 알림 받기 (담당자)

요청이 오면 저장소에 `[검토 요청]` 으로 시작하는 **Pull Request**(바뀐 내용이 있는 요청) 또는 **Issue**(메모만 보낸 요청)가 생기고, 본문에서 담당자를 불러 GitHub 이 알림을 보냅니다.

- 알림을 받을 GitHub 아이디는 로그인 중계 서버의 `REQUEST_REVIEWERS` 에 적습니다 ([설정 안내 14장](CMS-설정-안내.md#14-검토-요청-켜기)).
- 메일: GitHub → 오른쪽 위 사진 → **Settings** → **Notifications** 에서 **Email** 이 켜져 있는지 확인합니다.
- 휴대폰: GitHub 앱(Android·iPhone)을 설치하고 로그인한 뒤 알림을 켭니다. 앱에서 바로 확인·반영할 수 있습니다.
- 그래도 알림이 오지 않으면 저장소 페이지 위쪽 **Watch** → **All Activity** 를 고릅니다.

## 7. 요청 반영하기 (담당자)

**바뀐 내용 요청 (Pull Request)**

1. 알림의 링크를 누르거나 저장소 → **Pull requests** → `[검토 요청] …` 을 엽니다.
2. 본문의 **바뀌는 내용** 표(지금 사이트 ↔ 바꿀 내용)를 확인합니다. 줄 단위로 보려면 **Files changed** 탭을 엽니다.
3. 반영하려면 아래 **Merge pull request**(또는 **Squash and merge**) → **Confirm** 을 누릅니다. 1~2분 뒤 사이트에 반영됩니다.
   이어서 나오는 **Delete branch** 를 누르면 요청용 브랜치가 정리됩니다.
4. 반영하지 않으려면 아래 댓글 칸에 이유를 적고 **Close with comment** 를 누릅니다. 요청한 분은 관리 화면에서 ‘반영 안 함’과 댓글을 봅니다.
5. 조금 고쳐서 반영하고 싶으면, Merge 한 뒤 관리 화면(GitHub 계정으로 로그인)에서 그 항목을 고쳐 게시합니다.

**메모 요청 (Issue)**

1. 저장소 → **Issues** → `[검토 요청] …` 을 엽니다.
2. 내용대로 반영합니다. 관리 화면에 칸이 없는 것은 [홈페이지 관리 가이드 8장](홈페이지-관리-가이드.md#8-디자인레이아웃-바꾸기)의 방법으로 파일을 고칩니다.
3. 댓글로 처리 결과를 남기고 **Close issue** 를 누릅니다.

- 저장소 **Settings** → **General** → **Automatically delete head branches** 를 켜 두면 Merge 할 때 요청용 브랜치가 자동으로 지워집니다.
- 검토 요청은 `cms-request/…` 브랜치에 만들어지고 사이트는 `main` 에서만 배포되므로, Merge 하기 전에는 사이트가 바뀌지 않습니다.

## 8. 충돌이 났을 때 (담당자)

Pull Request 에 **This branch has conflicts** 가 보이면, 요청을 보낸 뒤 다른 사람이 같은 파일의 바로 옆 내용을 먼저 고친 경우입니다.

- 가장 쉬운 방법: 본문의 **바뀌는 내용** 표를 보며 관리 화면에서 직접 고쳐 게시한 뒤, 요청은 댓글을 남기고 **Close** 합니다.
- 또는 이 저장소를 PC 에서 열고 AI 코딩 도구(Claude Code 등)에 “Pull Request #번호 의 충돌을 해결해 병합해 줘”라고 부탁합니다.

## 9. 비밀번호 관리 (담당자)

- 비밀번호 바꾸기: Cloudflare → **Workers & Pages** → `lead-ai-lab-cms-auth` → **Settings** → **Variables and secrets** → `REQUEST_PASSCODE` 를 새 값으로 → **Deploy**.
  바꾸는 즉시 들어와 있던 사람도 모두 다시 들어와야 합니다.
- 모르는 요청이 오면(비밀번호가 새었을 때): 요청을 **Close** → **Delete branch** 하고 비밀번호를 바꾼 뒤, 새 비밀번호를 교수님께 직접 알립니다.
- 담당자가 바뀌면 `REQUEST_REVIEWERS` 를 새 담당자의 GitHub 아이디로 바꿉니다.
- 비밀번호는 12자 이상, 다른 곳에 쓰지 않는 것으로 정합니다. 메일 본문·단체 대화방·저장소·Dropbox 에 남기지 않습니다.
