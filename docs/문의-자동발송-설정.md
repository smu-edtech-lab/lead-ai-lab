# Contact 문의 자동 발송 설정 안내

Contact 페이지의 문의 폼에서 **보내기를 누르면 연구실 메일로 바로 발송**되게 하는 설정입니다.
홈페이지 담당자가 한 번 해 두면 됩니다. 걸리는 시간은 10~15분입니다.

이 사이트는 서버 없이 파일만 올려 둔 형태라서 혼자서는 메일을 보낼 수 없습니다.
그래서 연구실 **Google 계정 안에 작은 스크립트**(Google Apps Script)를 두고, 그 스크립트가 메일을 보내게 합니다.

### 지금 상태 (2026-11-15)

| 항목 | 값 |
|---|---|
| 사이트 설정 `contactEndpoint` (`content/site.ts`) | `null` — **자동 발송 꺼짐**. 보내기 버튼은 방문자의 메일 앱을 엽니다 |
| 발송 스크립트 | 코드만 준비됨(`contact-mail/Code.gs`). Google 계정에 아직 올리지 않음 |
| 받는 주소 | 미정 (관리 화면 ‘소속·연락처’의 문의 이메일 = `content/data/site.json` 의 `email` 은 배달되지 않는 예시 주소) |

설정을 마치면 이 표를 실제 값으로 고쳐 두세요. 어느 Google 계정에 만들었는지 적어 두어야 다음 담당자가 찾을 수 있습니다.

---

## 0. 한눈에 보기

```
방문자가 Contact 에서 [문의 보내기]
   │  입력 내용을 '웹 앱 주소'로 보냄
   ▼
Google Apps Script 웹 앱 (contact-mail/Code.gs — 연구실 Google 계정 안에서 실행)
   │  내용 검사 → 연구실 메일로 발송 (답장 받을 주소 = 문의한 사람)
   ▼
연구실 메일함 ── 받은 메일에 답장하면 문의한 사람에게 갑니다
```

- **필요한 것**: Google 계정 하나. 비용은 없습니다.
- **하루 발송 한도**: 일반 Google 계정 100통, Google Workspace 계정 1,500통 (Google 이 정한 값).
- **저장**: 문의 내용은 메일로만 전달됩니다. 스크립트나 사이트에 따로 쌓이지 않습니다.
- **화면 표시**: 스크립트가 "보냈다"고 답했을 때만 방문자에게 전송 완료를 보여 줍니다. 실패하면 입력 내용을 그대로 두고 다시 보내기·내용 복사·전화 문의를 안내합니다.

## 1. 어느 Google 계정으로 만들지 정하기

- **문의를 받을 메일함의 계정**으로 만들면 가장 간단합니다. 따로 적지 않아도 그 계정의 주소로 메일이 갑니다.
- 담당자 개인 계정보다 **연구실 공용 계정**을 권합니다. 담당자가 바뀌어도 그대로 쓸 수 있습니다.
- 다른 주소(예: 학교 메일)로 받고 싶으면 3단계의 `RECIPIENT` 에 그 주소를 적습니다.
- 학교·기관에서 준 Google 계정은 관리자가 외부 공개를 막아 둔 경우가 있을 수 있습니다. 5단계에서 **모든 사용자** 항목이 보이지 않으면 일반 Google 계정으로 만드세요.

## 2. 스크립트 만들기

1. 정한 계정으로 로그인한 브라우저에서 <https://script.google.com> 을 엽니다.
2. **새 프로젝트**(New project)를 누릅니다.
3. 왼쪽 위의 `제목 없는 프로젝트`를 눌러 이름을 바꿉니다. 예: `연구실 홈페이지 문의 발송`
4. 편집기에 들어 있는 `function myFunction() { … }` 를 모두 지웁니다.
5. 저장소의 [`contact-mail/Code.gs`](../contact-mail/Code.gs) 내용 **전체**를 복사해 붙여 넣습니다. GitHub 에서 파일을 열면 오른쪽 위에 복사 버튼(**Copy raw file**)이 있습니다.
6. 저장합니다(`Ctrl` + `S`).

> 화면의 메뉴 이름은 Google 이 바꾸는 일이 있어 이 문서와 조금 다를 수 있습니다. 괄호 안의 영어 이름을 함께 참고하세요.

## 3. 설정값 (필요할 때만)

붙여 넣은 코드 맨 위 `설정` 부분입니다. 그대로 두어도 동작합니다.

| 이름 | 기본값 | 뜻 |
|---|---|---|
| `RECIPIENT` | `''` (빈 값) | 문의를 받을 주소. 비워 두면 스크립트를 만든 계정의 주소. 여러 명이면 쉼표로 구분: `'a@x.ac.kr, b@x.ac.kr'` |
| `SUBJECT_PREFIX` | `[연구실 문의]` | 메일 제목 앞머리. 제목은 `[연구실 문의] 대학원 진학 문의 — 이름` 형태 |
| `SENDER_NAME` | `연구실 홈페이지 문의` | 받은 메일에 보낸 사람 이름으로 보이는 글자 |
| `MAX_PER_HOUR` | `20` | 한 시간에 보내는 최대 건수. 자동 프로그램이 하루 한도를 다 쓰지 못하게 막습니다 |
| `MIN_FILL_MS` | `3000` | 화면을 열고 3초 안에 제출되면 사람이 쓴 것이 아니라고 보고 거절합니다 |

## 4. 권한 승인과 시험 메일

1. 편집기 위쪽의 함수 선택 칸에서 **`testSend`** 를 고르고 **실행**(Run)을 누릅니다.
2. 승인 창이 뜨면 **권한 검토**(Review permissions)를 누르고 계정을 고릅니다.
3. `Google에서 확인하지 않은 앱` 화면이 나오면 **고급**(Advanced) → **(프로젝트 이름)(으)로 이동**을 누릅니다. Google 의 심사를 받지 않은 스크립트에 나오는 화면입니다. 지금은 방금 직접 만든 스크립트를 본인 계정에서 실행하는 것입니다.
4. 요청하는 권한은 두 가지입니다. **메일 보내기**와 **계정의 메일 주소 확인**. 권한마다 체크 칸이 보이면 모두 체크하고 **허용**(Allow)을 누릅니다.
   그 밖의 권한(드라이브, 메일 읽기 등)을 요청한다면 붙여 넣은 코드가 저장소의 것과 다른 것이니 멈추고 코드를 다시 확인하세요.
5. 아래 실행 로그에 `시험 메일을 보냈습니다. 받는 주소: …` 가 나옵니다. 그 메일함에 제목 `[연구실 문의] 시험 발송` 메일이 왔는지 확인합니다. 안 보이면 스팸함도 봅니다.

## 5. 웹 앱으로 배포하기

1. 오른쪽 위 **배포**(Deploy) → **새 배포**(New deployment)를 누릅니다.
2. `유형 선택`(Select type) 옆의 톱니바퀴 → **웹 앱**(Web app)을 고릅니다.
3. 아래처럼 채웁니다.

   | 칸 | 값 |
   |---|---|
   | 설명 (Description) | 아무 글자. 예: `문의 발송 1` |
   | 다음 사용자 인증 정보로 실행 (Execute as) | **나** (Me) |
   | 액세스 권한이 있는 사용자 (Who has access) | **모든 사용자** (Anyone) |

   `모든 사용자`여야 로그인하지 않은 방문자의 문의가 전달됩니다. `Google 계정이 있는 모든 사용자`가 아닙니다.
4. **배포**(Deploy)를 누르고, 나오는 **웹 앱 URL** 을 복사합니다. `https://script.google.com/macros/s/…/exec` 형태입니다.

이 주소는 비밀이 아닙니다. 사이트에 넣으면 방문자 브라우저에서도 보이는 값입니다. 받는 메일 주소는 스크립트 안에만 있고 사이트에는 드러나지 않습니다.

## 6. 주소 확인

로그인하지 않은 창(시크릿 창)에서 복사한 주소를 엽니다.

```
{"ok":true,"service":"contact-mail"}
```

이 글자가 보이면 정상입니다. Google 로그인 화면이 나오면 5단계의 액세스 설정이 `모든 사용자`인지 다시 확인하세요.

## 7. 사이트에 연결하기

두 곳을 고칩니다.

1. `content/site.ts` 의 `contactEndpoint` 에 복사한 웹 앱 주소를 넣습니다(파일 수정).

```ts
contactEndpoint: 'https://script.google.com/macros/s/…/exec' as string | null,
```

2. Contact 화면에 보여 줄 연구실 메일 주소는 관리 화면 **연구실 정보 › 소속·연락처** 의 **문의 이메일** 을 공개해도 되는 실제 주소로 바꾸고 **예시 주소** 를 끈 뒤 게시합니다(파일로는 `content/data/site.json` 의 `email`·`emailIsSample`).

- 메일 주소를 화면에 공개하지 않으려면 문의 이메일 칸을 비웁니다(`email: null`). 자동 발송은 주소 공개와 상관없이 동작합니다.
- `email` 을 예시 주소로 둔 채 `contactEndpoint` 만 넣어도 동작합니다. 이때 전송 실패 안내는 예시 주소로 보내라고 하지 않고 내용 복사와 전화 문의만 안내합니다.

고친 파일을 `main` 에 올리면 1~2분 뒤 사이트에 반영됩니다. 올리는 방법은 [홈페이지-관리-가이드.md 8장](홈페이지-관리-가이드.md#8-디자인레이아웃-바꾸기)에 있습니다.

연결하면 Contact 화면이 이렇게 바뀝니다.

| | 연결 전 | 연결 후 |
|---|---|---|
| 버튼 | 메일로 보내기 | 문의 보내기 |
| 누르면 | 방문자의 메일 앱이 열림 | 바로 발송. 보내는 중 → 전송 완료 |
| 실패하면 | — | 입력 내용을 그대로 두고 다시 보내기·내용 복사·전화 안내 |

## 8. 동작 확인

1. 공개 사이트의 Contact 에서 실제로 문의 한 건을 보냅니다.
2. `Thank you.` 와 전송 완료 문구가 보이는지 확인합니다.
3. 연구실 메일함에 메일이 왔는지 확인합니다. 처음에는 스팸함도 봅니다.
4. 그 메일에 **답장**을 눌러, 받는 사람이 문의할 때 적은 주소로 채워지는지 확인합니다.

## 9. 운영

**스크립트를 고쳤을 때** — 저장소의 `contact-mail/Code.gs` 를 고치고 편집기에 다시 붙여 넣은 뒤, **배포**(Deploy) → **배포 관리**(Manage deployments) → 연필(수정) → 버전을 **새 버전**(New version)으로 → **배포**. 이렇게 하면 주소가 그대로입니다. **새 배포**를 누르면 주소가 새로 생기므로 `contactEndpoint` 도 바꿔야 합니다.

**자동 발송 끄기** — `content/site.ts` 의 `contactEndpoint` 를 `null` 로 되돌리면 메일 앱 방식으로 돌아갑니다. 스크립트 쪽도 멈추려면 **배포 관리**에서 해당 배포를 **보관처리**(Archive)합니다.

**담당자나 계정이 바뀔 때** — 새 계정에서 2~6단계를 다시 하고 `contactEndpoint` 를 새 주소로 바꿉니다. 이전 계정의 배포는 보관처리합니다. 연구실 공용 계정에 만들었다면 계정을 넘겨받는 것으로 끝납니다.

**발송 기록 보기** — 편집기 왼쪽 **실행**(Executions)에서 요청마다 성공·실패를 볼 수 있습니다. 문의 내용은 여기에 남지 않습니다.

**스팸 문의가 올 때** — `MAX_PER_HOUR` 를 낮추고 새 버전으로 배포합니다. 계속되면 **새 배포**로 주소를 바꾸고 이전 배포를 보관처리합니다.

## 10. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 사이트에 `문의를 전송하지 못했습니다` 가 뜸 | 6단계처럼 주소를 열어 봅니다. 로그인 화면이면 액세스가 `모든 사용자`가 아닙니다. 코드를 고친 뒤 **새 버전**으로 배포했는지도 확인합니다 |
| 주소는 정상인데 계속 실패 | 편집기 **실행**(Executions)에서 실패 기록을 봅니다. 한 시간 20건(`MAX_PER_HOUR`)이나 하루 발송 한도를 넘으면 거절됩니다 |
| 전송 완료인데 메일이 없음 | 스팸함, `RECIPIENT` 오타. `testSend` 를 다시 실행해 같은 주소로 오는지 봅니다 |
| 승인이 필요하다는 오류 | 4단계의 `testSend` 를 다시 실행해 권한을 승인합니다 |
| `모든 사용자` 항목이 없음 | 기관 계정의 제한입니다. 일반 Google 계정으로 만듭니다 |

스크립트가 사이트에 돌려주는 답(개발 참고):

| 답 | 뜻 |
|---|---|
| `{ ok: true }` | 메일을 보냄 |
| `error: 'invalid'` + `field` | 입력값이 기준에 맞지 않음 (이름 80자, 이메일 형식, 소속 120자, 내용 10~5,000자, 동의) |
| `error: 'rejected'` | 자동 프로그램으로 판단 (숨은 칸이 채워짐, 3초 안에 제출) |
| `error: 'busy'` / `'quota'` | 한 시간 한도 / 하루 발송 한도 초과 |
| `error: 'bad_request'` / `'server'` | 형식이 다른 요청 / 스크립트 오류 |

입력값 검사 기준은 사이트(`components/forms/ContactForm.tsx`)와 스크립트 양쪽에 있습니다. 한쪽을 바꾸면 다른 쪽도 바꾸세요.

## 11. 개인정보

- 방문자가 적은 이름·이메일·소속·문의 내용은 Google 의 서버를 거쳐 연구실 메일함으로 전달됩니다. Contact 화면의 보내기 버튼 위에 이 사실을 적어 두었습니다.
- 스크립트는 문의 내용을 저장하지 않습니다. 메일함에 남은 문의는 연구실이 관리합니다. 처리가 끝난 문의를 언제 지울지 정해 두세요.
- 문의한 사람에게 자동 회신은 보내지 않습니다. 남의 주소를 적어 넣어 스팸을 보내는 통로가 되지 않게 하기 위해서입니다.
